# Production v2

Use `schema plan` as the canonical contract. Version 1 still loads; `migrate --plan OLD --output NEW` preserves the old file and adds explicitly inferred action beats for director review. It cannot infer an accurate Scene Bible from arbitrary prose. Old task inputs retain their original fingerprints when new fields stay at defaults. Changing non-default routing or direction binds new inputs; do not hide edits inside a resumed run.

## Director packet and continuity

`plan --plan INPUT --config CONFIG --out PROJECT` makes no paid requests and writes `run.json`, `shot_plan.json`, `director_plan.json`, `scene_bible.json`, `continuity_report.json`, `edit_decision_list.json` and `dialogue_plan.json`. It does not overwrite an existing workspace. Direct Codex authoring of v2 avoids an extra planning API call; `--story-file` is a separately budgeted Responses call.

`story_analysis` records logline, mainline, conflict, emotional arc, foreshadowing, reversal, climax and cliffhanger. Associate actual shots with `story_beat`. Vary shot duration according to thought, physical action and speech windows, within the chosen model's documented subset; do not standardize all shots to six seconds.

Each `action_beats` entry has `start`, `end`, `action`; beats cover the whole shot without gaps or overlaps. Shot action and `temporal_motion` must remain consistent with those beats. `blocking` describes screen position, gaze, prop, costume version and state. `focus`, `camera_instructions`, `director_instructions`, lighting and expression provide the shot's dramatic direction. Prompts reject overlength text rather than trimming necessary action. Review the compiled prompt for the selected model before production.

Scene Bible records location/layout/time/light/props. `continuity_in`/`continuity_out` track those plus axis, positions, gazes, held props, costumes, hair and behavior. Adjacent shots in the same scene compare overlapping declared state; a difference needs its exact field path (for example `held_props.lin_chen`) or field (`held_props`) in `intentional_changes`, and `change_reason`. A declared scene change breaks that comparison. Missing state is a review item, never evidence that continuity was observed. Versioned costumes require explicit matching references; same character identity/voice stays fixed.

`edit.kind` records hard cut, reverse shot, action match or scene change. These are motivated straight cuts; action-match correctness and eyelines are audiovisual review items. `entry_action`/`exit_action` explain action matches. `edit.audio_fade` applies short shot-audio edge fades; it does not invent missing picture handles or optical transitions. `source_asset_id` and actual source/task/hash records link the edit to media. `music_cues` can overlap, with timeline start/end, gain, fade-in/out and optional rights-declared file. Their overlapping ramps produce music crossfades. Dialogue receives sidechain priority; local limiter and sample-peak reports reduce/flag clipping, but do not certify a broadcast true-peak specification.

## Routing and model controls

`providers` prints the matrix in `scripts/capabilities.py`, checked against official documentation on 2026-10-20. This is the supported adapter subset, not a claim to implement every current provider feature. Kling 3 is deliberately limited to 3–10 seconds here; other durations need separately verified adapter coverage. Native Kling resolution is provider/model/mode dependent and always read from the returned stream. Runway's native ratios/dimensions are distinct from requested final export resolution; ordinary post-upscaling is disclosed.

Configure only providers/models you can access. Multiple model entries for the same provider are supported. The router first filters duration, input type, first/last-frame/Element, ratio and native-audio controls. `routing_policy=order` preserves configured order; `purpose` uses your `purposes`/`priority` declarations, and `cost` uses reviewed per-model ceilings. A shot can declare preferred provider/model, but incompatible controls still rule it out. Missing credentials skip a candidate during execution. There is no built-in assertion that one model is better at acting or animation. Record the selected routing reason, request parameters, actual model/task ID, raw output, raw hash, postprocessing and costs.

Image identity conditioning uses generated/imported first frames, or supported existing Kling Element IDs. It is not a universal multi-image video-reference interface. Native audio must be supported by the selected model; silent models cannot satisfy `preserve`. Text-to-video has weaker identity anchoring. Never resubmit an uncertain POST to try another model: reconcile the existing task and reservation first.

Official sources: [Runway API](https://docs.dev.runwayml.com/api/), [Runway OpenAPI](https://docs.dev.runwayml.com/openapi.json), [Kling official video docs](https://kling.ai/document-api/api/video/2-6/image-to-video/legacy), [OpenAI Images](https://developers.openai.com/api/docs/guides/image-generation), [Sync upload API](https://sync.so/docs/api-reference/api/generate-api/create-with-files).

## Motion and quality review

The motion engine uses [OpenCV LK optical flow](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html) and [RANSAC similarity fitting](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html), plus FFmpeg decoding. Uniform grayscale samples cover the complete clip (default 6 fps, at most 1,200 samples, reduced uniformly for long clips). Metrics include near-static pairs, repeated downsampled fingerprints, global transform, compensated residuals, planned/user/detector-labelled subject regions, temporal thirds, sudden visual changes and possible flashes. If no subject boxes are given, a center proxy is clearly labelled; it is not person detection or segmentation.

Planar camera transforms with little independent residual are suspicious, not conclusive. Real camera moves, parallax, changing light, compression, sparse features, anime timing and subtle acting can create false positives/negatives. Deliberate `hold` or `subtle` shots relax only the blanket freeze rejection and remain `needs_review`. Dark/black failures, decoding errors, wrong duration and absent required audio still stop. Never automatically turn an uncertain clip into a normal shot or a verified performance.

`quality_review.json` joins technical reports, motion, source integrity, duplication, continuity and exact-hash human decisions. `review --out PROJECT` is read-only. Record observations with `--target SHOT --scope motion|editorial --decision approve|reject --reviewer NAME --note OBSERVATION --sha256 HASH`. For uncertain raw footage before lip sync, add `--raw`; the task page exposes that original video. Old decisions do not apply to changed bytes. Rejecting a shot blocks final editorial approval. Approving a technically invalid file is not a repair.

The five evidence levels remain separate: **Offline Tested**, **Media Pipeline Verified**, **Provider Live Verified**, **Full Episode Rendered**, **Editorially Reviewed**. Release validation records the first two using offline fixtures. The last three are Pending in this release. A user-imported video can verify local media processing without verifying an AI provider. An exported rough cut is still `rendered_requires_editorial_review`. Final approval requires current technical integrity, all planned sources, no duplicate/rejected shots, and resolution of pending motion reviews. Actual identity, acting, dialogue, anatomy, mouth-to-speech alignment and subtitle glyph rendering require watching the media.

## Local workbench and local revisions

`studio --out PROJECT` binds only loopback with a random session token, rejects foreign Host/Origin, and serves registered project media with byte-range support. No external web assets or generation endpoint are used. The UI shows plan/characters/scenes/shots/tasks/errors/costs and original/synced/final previews. Review writes are protected by the project lock and current-media hash. The regenerate button copies a CLI command for explicit review/execution; it never submits a paid task. External reference images outside the project are not served; generated/project-local assets are eligible.

`regenerate` requires both paid flags and the original budget, even for a local revision request. It preserves old source versions, reuses matching character/image/TTS/SFX caches and applies a new video revision identity to exactly one shot. Keep ID/duration fixed; `--shot-file` may supply reviewed replacement direction. Unknown charges stop; known in-progress revisions resume the same task IDs. `max_attempts` bounds each provider's attempts and `max_shot_regenerations` bounds explicit revisions. All failures and uncertain charges keep reservations. The executor does not silently change these limits or the budget.

`render --out PROJECT` constructs no model client and performs zero paid calls. It reuses recorded source videos and mixed audio after hash checks; it can re-encode fps/size/color, recreate subtitles and music, and remux a fresh MP4. `--plan EDIT.json` allows reordering the same complete shot set and changing output/music. Changing shot durations/dialogue needs an explicit revision. It never loops/freezes/extends missing picture content. Source imports require `source_video` + `source_license`, retain origin and copied bytes, and are labelled user footage rather than model verification.
